# T3 Code بالعربية: دليل التشغيل من المصدر

هذه نسخة معرّبة من T3 Code. لا توجد لها ملفات تثبيت. تشغّلها من الكود المصدري كما يلي.

## ما هذه النسخة

- هذا فرع باسم `arabic` من نسخة منشقة (fork) عن المشروع الأصلي.
- النسخة المنشقة: https://github.com/3ssiri/t3code
- المشروع الأصلي: https://github.com/pingdotgg/t3code
- الرخصة: `MIT`، كما في ملف `LICENSE` في المستودع.
- الهدف: واجهة عربية كاملة تعمل من اليمين إلى اليسار.

```bash
git clone --branch arabic https://github.com/3ssiri/t3code.git
cd t3code
```

## المتطلبات

- الأداة `vp` (من Vite+): https://vite.plus
- الأداة `git`

الإصداران المطلوبان كما يحدّدهما `package.json`:

| الأداة  | الإصدار في `package.json` |
| ------ | ------------------------ |
| `node` | `26.13.1`                |
| `pnpm` | `12.14.0`                |

## التشغيل

من جذر المستودع، ثبّت الاعتماديات ثم شغّل الخادم والواجهة:

```bash
vp i
vp run dev
```

ثم افتح رابط الاقتران (pairing) الذي يطبعه المشغّل في الطرفية. فتح العنوان المجرد لا يكفي لتسجيل متصفح جديد.

تُحفظ بيانات التطوير في مجلد منفصل عن بيانات `T3 Code` المثبّت عندك، فلا يمسّ محادثاتك الحقيقية:

```text
~/.t3/dev
```

لتحديد مجلد آخر، أضف الخيار `--home-dir`:

```bash
vp run dev --home-dir <مجلد-البيانات>
```

### إن لم يظهر رابط الاقتران

حدث هذا على نظام `Windows`. أنشئ رابطًا جديدًا يدويًا بهذا الأمر، واستبدل المسار بمجلد بيانات التطوير عندك:

```bash
node apps/server/src/bin.ts pair --base-dir <مجلد-البيانات> --ttl 30m
```

- `<مجلد-البيانات>` هو مجلد بيانات التطوير المذكور أعلاه.
- مدة الرابط هنا 30 دقيقة.
- افتح الرابط الذي يطبعه الأمر في المتصفح.

## اختيار العربية

1. افتح الإعدادات (`Settings`).
2. اختر القسم العام (`General`).
3. افتح قائمة اللغة (`Language`).
4. اختر «العربية».

الترجمة ما زالت قيد العمل. كثير من النصوص ما زال بالإنجليزية، وستجد أسماء الأقسام والقوائم الإنجليزية ظاهرة بجانب العربية في أماكن.

## تشغيل سطح المكتب

```bash
vp run dev:desktop
```

## التحديث من المشروع الأصلي

أضف المستودع الأصلي مرة واحدة باسم `upstream`:

```bash
git remote add upstream https://github.com/pingdotgg/t3code.git
```

يلزم أيضًا تسجيل الدخول في أداة `gh` للقراءة فقط، ليقرأ السكربت حالة طلب الدمج في المشروع الأصلي.

ثم شغّل السكربت:

```bash
node scripts/arabic/weekly-sync.mjs --dry-run
node scripts/arabic/weekly-sync.mjs
```

- `--dry-run` يجرّب دون تغيير شيء.
- بلا خيارات: يدمج ويحفظ محليًا فقط.
- `--push` يرفع النتيجة أيضًا بعد نجاح الدمج.
- إن فشلت أي خطوة بعد الدمج، يعود المستودع إلى حاله السابقة.

رموز الخروج عند الفشل:

| الرمز | المعنى                           |
| ----- | -------------------------------- |
| 1     | في المستودع تغييرات غير محفوظة   |
| 2     | تعارض أثناء الدمج                |
| 3     | أُعيدت كتابة فرع المشروع الأصلي    |
| 4     | فشل فحص الترجمة (`i18n:check`)   |
| 5     | فشل أمر خارجي                    |
| 6     | لست على فرع `arabic`             |
| 7     | الإصدار المسجّل غير معروف لـ `git` |
| 8     | خطأ غير متوقع                    |
| 9     | فشل الرفع، والحفظ المحلي باقٍ     |
| 10    | فشل الدمج دون تعارضات            |
| 11    | فشل التراجع، ويلزم إصلاح يدوي     |
